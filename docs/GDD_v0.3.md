# 1. 게임의 중심

**미사일을 모으고 발사대를 늘려 도시를 부수고, 성장한 화력으로 내 기지에 떨어지는 거대 핵미사일을 격추해 다음 월드로 진입하는 파괴 성장 시뮬레이터.**

Roblox PC·모바일을 대상으로 한다. 플레이어에게 주고 싶은 감정은 “한 발로 작은 주택을 부수던 내가 여러 발을 연속 발사하며 큰 도시를 무너뜨린다”다. 타깃은 복잡한 조작보다 수집·파괴·눈에 보이는 성장을 원하는 이용자로 가정한다. 실제 이용자 반응은 테스트로 확인한다.

개발 인원·아티스트 투입·출시일은 확정하지 않는다. v0.1의 3월드 출시 지향은 유지하되 **즉시 제작할 검증 범위**와 **출시 콘텐츠 범위**를 구분한다.

# 3. 코어 루프와 플레이어 행동

**광장에서 기지 차지 → 기지 제작·장착 → 내 대로로 출격 → 이동하며 자동 공격 → 중요한 대상 집중 발사 → 파괴 → 부품 회수 → 제작/장착 개선 → 도시 완파 → 보스 도전 → 다음 월드.**

순간 행동은 이동·목표 선택·집중 발사·회수 네 가지로 시작한다. “왜 다음 위치로 가야 하는가”, “왜 이 목표부터 부수는가”가 보이게 만든다. 첫 실험에서는 액티브 스킬을 추가하지 않고 이 네 가지가 충분히 작동하는지 확인한다.

오버드라이브·약점·EMP 등 특수 미사일은 기존 v0.1의 후보로 보존하되, 도시와 보스 기본 루프 이후에 한 개씩 실험한다. 점프 퍼즐·QTE·별도 미니게임은 현재 검증 범위에서 제외한다.

# 5. 성장 구조 — 제안

## 검증 단계 A: 현행 시스템으로 재미 확인

첫 미사일→두 번째 미사일→3~5개 장착→첫 완파를 관찰한다. 스탠더드만 가진 테스트 조건과 실제 확률 조건을 따로 측정한다. 기본 제작비·희귀도·사거리를 동시에 변경하지 않는다.

기본 장착 한도는 3발이다(2026-11-13 사용자 결정, 이전 테스트 값 10). “장착 수가 늘면 명확히 빨라지는가”는 기술 개발 연구로 확인한다. 100칸 정리 기능은 제작을 계속할 수 있는 최소 조건으로 구현한다. 정책은 장착·즐겨찾기 보호가 있는 부품 환원 또는 삭제 중 하나를 선택한다. 환원율은 경제 테스트 후 정하며 아직 확정하지 않는다.

## 확장 단계 B: 확정 성장과 수집 성장 분리

**이전 제안:** 도시 완료로 슬롯이 열리고 제작으로 채우는 구조. 2026-11-13 결정으로 첫 기술 개발 항목을 **미사일 장착 개수 업그레이드**로 정했다. 아래 마일스톤·수치는 참고 후보이며 최신 설계는 5-1절을 따른다. 좋은 희귀도가 나오지 않아도 다음 단계로 나아갈 수 있어야 한다.

| 마일스톤 | 슬롯 한도 제안 | 보여줄 변화 |
| --- | --- | --- |
| 첫 접속 | 1 | 단발 장비 |
| 첫 도시 | 3 | 양옆 장비 확장 |
| 월드1 보스 | 5 | 첫 완성 랙 |
| 월드2 보스 | 8 | 두 줄 랙 |
| 월드3 초반 | 10 | 최대 랙 |

이 표는 현행 고정10과 다르며 별도 저장·로드·UI·Config.Count 수정이 필요하다. 초반 수집감이 지나치게 막히면 1→3 구간을 첫 튜토리얼 완료로 당기는 안을 비교한다.

공격력·발사속도·크리티컬·크리피해·추가타·추추가타는 모두 v0.1 후보를 유지한다. 첫 출시 검증에는 공격력 또는 발사주기 중 한 축만 추가하고, 크리티컬과 연쇄 추가타는 후순위로 둔다. 여러 승산형 능력치를 동시에 넣어 밸런스 원인을 잃지 않게 한다.

# 5-1. 연구 시스템 — 시설 분리와 첫 개발 항목

2026-11-13 사용자 결정 반영. 아래는 추가 기획이며 연구 기능의 구현 완료를 뜻하지 않는다.

## 확정한 방향

- 연구 시설은 **AFK 연구동**과 **기술 개발 연구시설**로 구분한다. 같은 이름·같은 기능처럼 보이지 않게 한다.
- 가장 먼저 만들 기술 개발 항목은 **미사일 장착 개수 업그레이드**다.
- 기술 개발 화면은 시설에서 상호작용하는 방식 외에 **화면 UI 버튼으로도 열 수 있어야 한다**.
- 앞의 도시·보스 마일스톤만으로 슬롯을 여는 안은 이전 제안이다. 장착 수 성장은 기술 개발을 우선으로 설계하며, 도시·보스 조건의 연계 여부는 별도로 정한다.
- 기존 재화 역할을 유지한다. 능력 성장에는 연구자료를 쓰고, 전시장 등 시설 공간 확장은 코인을 쓴다. 단 타이쿤의 중요한 갈림길에는 연구자료를 조금 함께 낸다(아래 갈림길 규칙, 시험). 세부 비용은 미정이다.

## 두 시설의 역할

| 구분 | AFK 연구동 | 기술 개발 연구시설 |
| --- | --- | --- |
| 목적 | 머무는 시간을 활용하는 보조 성장 콘텐츠 | 플레이어가 연구 항목을 선택하고 능력을 영구 강화하는 메뉴 |
| 첫 구현 우선순위 | 기술 개발 이후. 먼저 보상과 시간 규칙을 정한다 | 최우선: 미사일 장착 개수 업그레이드 |
| 사용 방식 | 정해진 AFK 구역에 머무는 흐름을 제안 | 기지 시설 상호작용 또는 HUD의 기술 개발 버튼으로 동일 화면 열기 |
| 확정하지 않은 것 | 보상 종류·지급 주기·상한·오프라인 인정·중단 시 처리 | 최초 장착 한도·단계별 증가량·비용·선행 조건·개발 시간 |
| 구분할 표현 | 대기 구역·진행 시간·보상 표시를 가진 연구동 제안 | 설계도/기술 트리 화면이 있는 단말·작업대 제안 |

AFK 연구동을 이용해야만 첫 장착 수 연구가 가능한 구조인지는 결정하지 않았다. AFK가 필수 병목이 되지 않도록 첫 연구자료 공급 경로를 함께 검토한다. 2026-11-13 맵 외형 반영: 기지6개 뒤쪽에 보라색 AFK 대기실(의자·시계·돔)과 청록색 기술 개발실(작업대·설계도·단말)을 분리 배치했다. 두 시설은 별도 간판으로 구분한다. AFK 지급·기술 개발 메뉴와 연구 기능은 후속이다.

## 연구 관련 시설 배치와 화면 구성 (2026-11-13 사용자 결정)

"연구"라는 이름의 기능을 **플레이어가 하는 행동**으로 나눈다. 확정 강화와 무작위 뽑기를 한 메뉴에 섞지 않는다.

| 기지 구역 | 시설 | 하는 일 | 재화 |
| --- | --- | --- | --- |
| 제작 구역(앞) | 제작대들 + **제작대 등급 업그레이드 단말**(5-2절) | 미사일 만들기 · 나오는 미사일 좋게 하기 | 제작 코인 / 등급은 갈림길 규칙(코인 + 연구자료 조금, 시험) |
| 연구 구역(뒤) | ① **기술 개발 단말** | 확정 강화(장착 수 등). 고르고 사면 반드시 오름 | 연구자료 |
| 연구 구역(뒤) | ② **패시브 뽑기 장치** | 무작위 패시브 뽑기 | 미정 |
| 연구 구역(뒤) | ③ **AFK 연구동** | 머무르며 연구자료 벌기 | 시간 |

- 연구 구역은 기지 뒤쪽 한곳에 모은다. "연구자료를 벌고 쓰는 동네"로 묶고, 앞쪽 입구→제작→출격 동선을 막지 않는다. 좌표는 레벨디자인 2-1절.
- 겉모습: 연구자료를 쓰는 물건(등급 단말·기술 개발 단말)은 연구자료 색·설계도 아이콘으로 통일한다. 코인 시설(전시장 칸·제작대 추가)은 코인 색. 패시브 뽑기 장치는 캡슐 기계처럼 생겨 "운"이 보이게 한다. 가격표는 숫자보다 재화 아이콘을 크게.
- **HUD는 "연구" 버튼 하나 + 탭 두 개(기술 개발 | 패시브)**. 기지 안에서는 시설마다 E로 해당 탭을 바로 연다. AFK 연구동은 그 자리에 머무는 콘텐츠라 HUD에 넣지 않는다. 제작대 등급은 제작 구역 단말에서만(HUD 포함 여부 미정).
- 패시브 뽑기의 재화·확률·패시브 목록·중복 처리는 미정.
- **타이쿤 갈림길 규칙 (2026-11-13 사용자 결정, 시험 적용):** 타이쿤 시설은 기본적으로 코인이지만, **중요한 갈림길**(제작대 등급, 주요 시설 해금 등 성장 방향이 크게 바뀌는 단계)에는 **연구자료를 조금** 함께 낸다. 일반 칸 확장(전시장 칸 등)은 코인만. 어느 단계가 갈림길인지, 연구자료 양은 미정이며 플레이 후 조정한다. 연구자료가 드는 단계는 가격표에 연구자료 아이콘을 함께 보여준다.

## 첫 기술: 미사일 장착 개수 업그레이드

플레이어가 동시에 장착하고 전투에 사용하는 미사일의 최대 수를 늘린다. 미사일을 지급하는 기능이 아니므로 늘어난 슬롯에는 보유 미사일을 장착한다. 인벤토리 보관 용량이나 기지 전시장 칸 확장과도 구분한다.

- 화면에는 현재 한도, 다음 한도, 보유 연구자료, 필요 비용, 선행 조건을 표시한다.
- 개발 성공 후 장착 화면의 한도와 실제 전투 슬롯에 같은 값이 반영되어야 한다.
- 연구 레벨은 저장하고 재접속·기지 변경·낮밤 전환 후에도 유지하는 방식으로 설계한다.
- 2026-11-13 사용자 결정·적용: 기본 장착 한도는 3발이다. 미사일은 제작하면서 채운다. 연구 성장 연결 전에는 한도를 3으로 고정한다. 기존 보유·장착 저장 데이터는 삭제하지 않고 전투에는 앞의 3발까지 사용한다. 기존 초과 장착 데이터의 정식 전환 규칙은 연구 구현 때 결정한다.
- **시작 한도 확정: 3발. 수치 미정:** 연구 후 최대 한도, 한 단계당 증가량, 각 단계 비용. 기존 1→3→5→8→10 표는 후보이며 이번에 확정한 값이 아니다.

## 기술 개발 UI 흐름

**HUD의 기술 개발 버튼 또는 시설 상호작용 → 같은 기술 개발 화면 → 미사일 장착 개수 카드 → 현재/다음 효과와 비용 확인 → 개발 → 한도·잔액·연구 레벨 갱신.**

- 제안: HUD에서는 기지 밖에서도 메뉴를 열 수 있게 하고 시설 해금 조건은 두 진입 경로에 동일하게 적용한다. 정확한 접근 제한은 구현 전에 결정한다.
- 초기 화면은 첫 기술 카드 하나를 우선 노출한다. 후속 연구 트리를 미리 복잡하게 채우지 않는다.
- 개발 가능 / 연구자료 부족 / 선행 조건 미충족 / 최고 단계 / 처리 중 상태를 구별한다.
- AFK 시간·보상 화면은 별도로 둔다. 기술 개발 버튼이 AFK 대기 화면으로 연결되면 안 된다.
- PC·모바일에서 같은 기능을 사용할 수 있어야 하며, Studio Edit에서도 메뉴와 잠금 상태 미리보기를 제공한다.

## 구현 시작 순서와 완료 기준

1. 단계·연구자료 비용·연구 해금 조건·기존 데이터 전환 규칙을 확정한다(최초 장착 수는 3발로 결정·적용).
2. 연구 레벨 저장과 서버의 현재 장착 한도 계산을 연결한다.
3. 서버에서 연구자료 잔액·선행 조건·최대 단계·중복 요청을 검사하고 결제와 레벨 상승을 함께 처리한다.
4. 기술 개발 시설의 진입점과 HUD 버튼이 동일 메뉴·동일 서버 처리로 이어지게 만든다.
5. 장착 UI·제작 자동 장착·전투 발사 한도에 같은 값을 적용하고 재접속 보존을 검증한다.
6. 그다음 AFK 연구동의 보상·시간·상한을 확정하고 별도로 구현한다.

검증할 것: 연구 성공 시 정확한 비용 차감과 한도 증가, 잔액 부족/중복 입력 시 잘못된 결제 없음, 한도 초과 장착 거절, 재접속 보존, 시설/화면 버튼의 동일 동작, AFK 화면과 명확한 구분.

# 5-2. 미사일 연구 — 제작대 등급과 미사일 풀

2026-11-13 사용자 결정(Claude와 논의). **기획이며 미구현.** 같은 날 위치를 바꿨다: 기술 개발 연구시설 메뉴가 아니라 **제작 라인 옆 업그레이드 단말(타이쿤식)**에서 올린다. 레벨별 등장 미사일 종류 수는 구글 시트 MS_MASTER의 **MISSILES 탭(사용자 탭, AI는 읽기만)**을 기준으로 한다.

## 결정한 방향

- **제작 라인 옆 업그레이드 단말**에 다가가 E로 "미사일 제작대 등급(미사일 연구 레벨)"을 올린다(타이쿤식). 기술 개발 연구시설 메뉴에는 넣지 않는다.
- 비용: 5-1절의 **타이쿤 갈림길 규칙**(코인 + 연구자료 조금, 2026-11-13 시험 적용)을 따른다. 양은 미정. 연구자료 색·아이콘을 단말 외형과 가격표에 써서 코인만 쓰는 시설과 구분한다.
- 등급은 플레이어 하나에 하나다. **기지의 모든 제작대에 한 번에 적용**한다. 제작대마다 따로 올리지 않는다.
- 제작대 개별 성장은 코인 쪽(기지 타이쿤)으로 분리한다. 후보: 제작대 추가 해금(1→6대), 대당 제작 속도·외형. 미정.
- 화면 이름은 결과가 보이게 한다: "제작대 등급" 또는 "제작 가능 미사일 확장". "연구 레벨"만 단독으로 쓰지 않는다.
- 연구시설(기술 개발·AFK·패시브 뽑기) 화면 구성은 별도 논의 중.

## 레벨업 적용 규칙

- 업그레이드 즉시 적용한다. HUD에서도 올릴 수 있게 할지는 미정.
- **진행 중인 제작은 시작 때 정해진 결과(PendingRoll)를 유지**하고, 다음 제작부터 새 풀을 쓴다. 진행 중 결과를 바꾸지 않는다.
- 개발 시간을 둘 경우 시간이 끝난 순간 적용하고, 오프라인이었다면 다음 접속 때 적용한다. 개발 시간 유무는 미정.
- 나중에 해금하는 제작대는 처음부터 현재 등급의 모습·풀로 나타난다.
- 등급 저장은 재접속·기지 변경·낮밤 전환 후에도 유지한다.

## 미사일 풀 설계

MISSILES 탭은 레벨마다 등장 종류 합계가 **8종으로 같다**. 레벨이 오르면 종류 수가 아니라 **희귀도 범위가 위로 이동**한다(4레벨부터 커먼·언커먼 0).

1. **2단계 뽑기:** 레벨별 희귀도 확률표로 등급을 먼저 뽑고, 그 등급 안의 미사일을 같은 확률로 고른다. 종류가 추가돼도 다른 등급 확률이 희석되지 않는다.
2. **레벨별 상대 확률표:** 그 레벨의 가장 낮은 등급 약 50~60%, 가장 높은 등급 약 1% 모양을 유지한다(현행 60/25/10/4/1과 같은 형태). 한 레벨에 등장하는 등급은 5~6개로 제한하고, 0인 등급은 표에서 뺀다. 정확한 값은 미정. 초안은 별도 탭(예: MISSILE_RESEARCH_DRAFT)에 만들고 MISSILES 탭은 고치지 않는다.
3. **레벨업 직후 새 미사일 보장:** 연구 완료 후 첫 제작(또는 첫 3회 안)에서 이번 레벨에 새로 추가된 미사일 하나를 확정 지급한다. 최상위 등급 천장(N회 안 1번)은 미정.
4. **빠지는 미사일:** 레벨업 화면에 "새로 등장 / 더 이상 안 나옴"을 함께 표시한다. 빠진 미사일은 도감에 "이전 연구 레벨"로 남긴다. 제작대에서 낮은 레벨을 골라 제작하는 기능은 넣지 않는다.
5. **피해 배율 확장:** 현행 5등급(1/1.3/1.8/2.5/4)을 MISSILES 탭의 등급(커먼~시크릿)까지 늘려야 한다. 레벨당 평균 1발 피해 상승 목표(예: +30~50%)를 먼저 정하고 확률표·배율을 맞춘다. 미정.

## 유저에게 알리는 방법 (UI 요구사항)

그냥 두면 유저는 "제작대 레벨업 = 풀 확장"을 알 수 없다. 세 시점에서 직접 보여준다.

| 시점 | 보여줄 것 |
| --- | --- |
| 연구 전 | 업그레이드 단말 화면에 "제작대 등급 Lv.N → N+1"과 **"새로 등장"** 미사일 아이콘(미보유는 실루엣 + 희귀도 색). 제작대 프롬프트 옆 **"등장 목록"** 버튼: 현재 등급의 미사일과 등급별 확률, 다음 등급 미사일은 잠긴 실루엣 + "Lv.N 필요" |
| 완료 순간 | 기지 제작대 전부가 동시에 빛나며 외형 변경(1~2초) + 효과음. 팝업 "새 미사일 N종 등장!" + 아이콘, 빠지는 등급이 있으면 "이제 커먼은 나오지 않습니다" |
| 이후 제작 | 첫 제작 새 미사일 보장, 처음 얻은 미사일 **NEW 배지**, 도감 칸 채움, 제작 결과 알림에 "Lv.N 신규" 표시. 제작대 프롬프트에 "제작 · 코인 20 · 등급 Lv.N" |

- 제작대 외형은 등급마다 구분되게 한다(색·부품 추가·등급 표지판). 프로토타입에서도 모양·색으로 구분한다. 몇 단계로 나눌지(6단계 전부 또는 2~3단계마다)는 미정.
- 등장 목록(확률 공개) 화면은 처음부터 만든다. 나중에 로벅스 관련 제작 상품을 팔면 Roblox 정책상 유료 랜덤 아이템 확률 공개가 필요하다.
- 검증: 신규 이용자 테스트에서 연구 후 "연구하면 뭐가 좋아졌나요?"를 묻고 "더 좋은 미사일이 나온다"고 답하는 비율을 기록한다.

## 미정 (구현 전에 사용자 확인)

- MISSILES 탭의 "1~4레벨"과 "5맵·6맵" 표기: 연구 등급이 곧 맵(월드) 진행인지, 따로 오르고 구역·월드 완파를 선행 조건으로 거는지.
- 등급별 연구자료 비용, 개발 시간 유무, 레벨별 희귀도 확률값, 새 등급 피해 배율, 제작대 외형 단계 수, 카드 공개 순서.
- 연구자료 공급: 1구역 8채 완파당 기대값 약 1.2개라 비용을 정하기 전에 공급 경로(완파 보상 확정 지급 등)를 함께 정한다.

## 구현할 때 순서 (제안)

1. 위 미정 항목 확인 → 레벨별 희귀도 확률표·배율 초안 탭 작성 → 사용자 승인.
2. 등급 저장 + 서버 제작 풀 계산(2단계 뽑기, PendingRoll 유지, 레벨업 직후 보장).
3. 제작 라인 옆 업그레이드 단말(모델·E 프롬프트·화면) + 제작대 "등장 목록" 화면.
4. 완료 연출(전체 제작대 외형 변경·팝업)·NEW 배지·도감 연결, StarterGui 미리보기 사본 갱신.
5. 검증: 정확한 비용 차감, 진행 중 제작 결과 불변, 다음 제작부터 새 풀, 보장 1회, 재접속 보존, 확률표 합 100%.

월드2는 현재 HP4배·동일보상이다. **다음 지역이 더 좋은 성장 선택이라는 근거가 필요하다.** 첫 비교안은 월드2 부품 보상을4배로 올려 피해당 보상을 맞추는 것이지만, 이것만으로 분당 효율 개선을 보장하지 않는다. 이동·클리어·귀환·제작을 포함한 실측으로 새로 도달한 월드의 부품/분이 이전 월드보다 약10~25% 높은 후보를 찾는다. 이 수치는 내부 실험 목표이며 외부 벤치마크가 아니다.

보스의 연구자료 확정 보상은 소비처·해금 구조가 정해진 뒤 도입한다. 첫 보스의 확정 보상은 다음 월드 해금과 슬롯 마일스톤을 우선 후보로 둔다. 일반 도시에서는 탈것이 이동 편의를 준다. 개인 보스 구역 진입에는 비행 업그레이드가 필요하다.

# 7. 도시·월드 진행 — 제안

## 용어

- 목표물: 주택·상가·공장 등 한 개의 파괴 판정 단위.
- 도시: 목표물 묶음과 짧은 완파 목표.
- 월드: 도시 여러 개와 보스가 묶인 챕터.
- 반복 런: 이미 해금한 도시를 다시 파밍하는 단위.

현재 코드에서는 월드당4목표 묶음이 사실상 도시 하나다. 이 문서의 도시 여러 개 구조를 적용하려면 WorldId→CityId→BuildingId 계층과 영구 완료 기록이 추가로 필요하다.

## 공간 구조 (v0.3 적용)

월드1은 **원형 광장 + 기지별 진격 대로**다. 광장 둘레에 기지 6개가 있고, 각 기지 뒤로 자기만의 대로가 바깥으로 뻗는다. v0.3에서는 "도시"를 **대로 위의 구역**으로 배치한다.

- 광장: 공용·사회 공간. 다른 플레이어의 기지와 발사대 성장이 보인다. 가운데는 **공동 보스 레이드 자리**(예정)라 평소엔 전투 없음.
- 기지(타이쿤): 80×110 개인 공간. 제작 라인(여러 대 동시 제작), 미사일 전시장(도감과 연결), 기지 차고(탈것 소환·전시), AFK 연구시설(방치 성장). 도시 파괴가 주 성장이고 기지는 보조라는 v0.1 원칙은 유지.
- 대로: 개인 공간. 구역1(주택가) → 구역2(상업가) → 구역3(연구구역) → 보스장 순으로 멀어질수록 강해진다.
- 버기: 구역2부터 이동 편의를 크게 높이는 선택 성장. 필수 관문으로 막지 않는다.
- 남의 기지를 터는 PvP는 넣지 않는다. 공용 이벤트(광장 보급 코어 등)는 MVP 이후 후보.

치수·좌표·동작 계약은 [레벨디자인 실행안 v0.3](LEVEL_DESIGN_v0.3.md)을 따른다.

## 출시 지향 구성안

| 월드 | 테마 후보 | 도시3개 제안 | 보스 역할 |
| --- | --- | --- | --- |
| 1 | 외곽 생활도시 | 대로 위 구역: 주택가→상업가→연구구역 | 핵미사일1발, 기본 화력 학습 |
| 2 | 산업지대 | 창고지대→공장구역→발전구역 | 더 큰 핵미사일 + 빛나는 약점(집중 발사) |
| 3 | 거대 기계도시 | 외곽시설→고층중심→중앙요새 | 가장 큰 핵미사일, 체력30%에서 분리 → 남은 조각까지 요격 |

도시 수·테마는 제작량 산정을 위한 초안이다. 현재4건물 모델은 월드1 그레이박스에 우선 재사용한다. 3월드 아트에 바로 착수하지 않고 **월드1 도시3개+보스1종**의 완성도를 먼저 확인한다.

# 8. 진행 보존과 낮밤 — 제안

기본 권장안은 **낮밤을 분위기·선택 보너스로 사용하고, 신규 튜토리얼과 필수 도시 진행은 전역 밤 때문에 중단되지 않게 하는 것**이다. 현재 밤 공격불가 정책을 바꾸는 제안이다.

영구 데이터는 도시 최초 완료·보스 격파·월드 해금이고, 반복 데이터는 현재 런의 파괴 목표·드롭이다. 밤이 되거나 반복 런을 초기화해도 영구 해금은 유지한다. 미완료 런의 부분 진척을 저장할지 여부는 데이터 비용과 악용 테스트 후 결정하되, 사용자에게 리셋 시점을 명확히 알린다.

최소 실험에서는 별도 개발용 사본에서 낮을 고정해 동선만 비교하고, 그다음 현행 낮밤을 켠 결과와 비교한다. 이는 테스트 절차이며 라이브 설정을 이미 바꿨다는 뜻이 아니다.

현재4건물 루프가15분을 보장한다는 뜻은 아니다. 현재180초 낮 제한과 그대로 공존할 수도 없으므로 먼저 A단계 실측을 한 뒤 B단계 콘텐츠 양을 정한다. 지연을 위해 걷기·체력만 늘리지는 않는다.

# 10. 보스: 핵미사일 요격 — 비행으로 구역 진입, 미구현

**2026-11-10 진입 결정:** 탈것을 업그레이드해 비행을 해금한 뒤, 지형이 끊긴 구간을 직접 날아 보스 구역에 착륙한다. 업그레이드 전에도 목적지는 보이지만 걷기·점프·지상 탈것으로는 건널 수 없다. 단절 지형으로 진입 조건을 보여준다. 적용 범위는 월드 진행용 개인 보스로 해석했다.

모든 월드에서 규칙은 같고 숫자와 추가 요소 하나만 바꾼다: 월드1은 기본, 월드2는 빛나는 약점(집중 발사로 추가 피해), 월드3은 체력 30%에서 작은 미사일로 분리. 상세 수치·파일 계획은 레벨디자인 v0.3 10절.

- 성공: HP0 → 공중 대폭발, 영구 보스 완료·다음 월드 해금, 보상1회 처리.
- 실패: 요격 제한을 넘기면 대폭발 연출. **기지·장비·자원 손실 없음.** 핵미사일의 구체적인 등장 위치·이동·충돌 지점은 새 보스 구역에서 다시 정한다.
- 재도전: 5초 이내 다시 시작.
- 밤: 기본안은 보스전을 밤 공격 거절에서 제외(대안: 남은 낮 40초 미만이면 시작 금지).
- 보류한 후보: 돌진 빌딩(벽에 찌부), 도망가는 보스. 이유는 레벨디자인 v0.3 10절.
- UI: 남은 거리/시간, HP, “화력 부족/사거리 이탈”을 구분할 정보.
- 화력 산정: 목표 장착 조건의 실제 유효 DPS 중앙값×도전시간을 출발점으로 사용. 임의 피해÷1.6 계산을 쓰지 않음.
- 초기 가설: 표준 목표 장비로20~30초 내 성공, 도전시간30~40초. 전부 실험값이며 플레이 실측 후 변경.

보스2·3은 같은 서버 상태·이동·보상 처리 틀을 재사용한다. 약점·회피·복수 목표는 첫 보스 재미가 확인된 뒤 하나씩 추가한다.

# 11. 레벨·UI·아트 원칙

대로 입구에서 첫 목표와 다음 랜드마크가 보이게 한다. 광장에서는 내 기지와 내 대로 입구를 바로 찾을 수 있어야 한다. 전부 사거리 안에 밀집시키지 않고, 짧은 공격→회수→새 구역 진입을 반복하게 한다. 큰 건물·보스는 실루엣으로 다음 목표를 예고한다. 구체 치수와 제작 순서는 연결된 레벨디자인 문서를 따른다.

화면은 현재 목표1개, 장착/재장전, 부품, 진행률을 우선한다. 연구 소비가 없으면 연구자료를 부품보다 강하게 강조하지 않는다. 제작 완료는 전투 입력을 막지 않는 알림을 우선 검토한다. 모바일에서는 이동·카메라·집중 발사 영역이 겹치지 않아야 한다.

**UI 색·모양 (2026-11-09 적용, 사용자 선택 v03):** Codex 시안 `art/references/toy-city-v03/ui/01-gameplay-hud.png` 기준 밝은 장난감 스타일. 흰 패널(248,251,255)+연한 파랑 테두리, 진한 남색 글자(28,44,82), 파란 알약 버튼(40,110,230), 초록 확인, 주황 경고, 빨강 닫기, 연회색 비활성, 진한 노랑 부품·파랑 연구자료, 모서리 12. 밝은 희귀도 글자는 같은 색조로 어둡게 바꿔 흰 바탕에서 읽히게 함. 아트는 미사일 랙 성장 실루엣,4건물 모듈 키트, 보스 핵미사일(월드별 크기 3종)과 대폭발, 회수·제작·폭발 피드백 순으로 제작한다. 그레이박스에서 통과한 피벗·충돌·실루엣 규격을 유지하며 교체한다. 인원 확보나 외주 계약은 아직 확정하지 않는다.

# 13. 수익화와 운영

이번 검증은 비과금으로 코어 루프가 성립하는지 확인한다. 유료 슬롯·속도·확률 변경은 경제와 저장·상품 처리 설계 후 별도 문서로 정한다. 현재 영수증 처리 구현은 확인하지 못했다.

출시 후 콘텐츠 단위는 도시 또는 보스 변형 한 묶음으로 제안한다. 업데이트마다 새 화폐·새 시스템을 동시에 추가하지 않고, 목표 도달시간·다음 지역 효율·재방문 동기를 확인한다. 결제·거래 기능을 이번 요청에서 구현하거나 설정하지 않았다.
